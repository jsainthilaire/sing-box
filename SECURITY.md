## Reporting a Vulnerability

We take security vulnerabilities seriously. If you believe you have found a security vulnerability in sing-box, please follow these steps:

### 1. **DO NOT** create a public GitHub issue
Security vulnerabilities should be reported privately to prevent potential exploitation.

### 2. **DO NOT** disclose the vulnerability publicly
This includes social media, public forums, or other public channels.

### 3. **Report privately** using one of these methods:

#### Option A: GitHub Security Advisories (Recommended)
1. Go to the Security tab in this repository
2. Click on "Report a vulnerability"
3. Fill out the security advisory form with detailed information

#### Option B: Email Security Team
Send an email to: **security@sager.net**

### 4. **Include the following information** in your report:

- **Description**: Clear description of the vulnerability
- **Steps to reproduce**: Detailed steps to reproduce the issue
- **Impact**: Potential impact of the vulnerability
- **Affected versions**: Which versions are affected
- **Proof of concept**: If available, include a proof of concept
- **Suggested fix**: If you have suggestions for fixing the issue

### 5. **What to expect**:

- **Initial response**: Within 48 hours
- **Status updates**: Regular updates on the progress
- **Timeline**: We aim to address critical vulnerabilities within 7 days
- **Credit**: You will be credited in the security advisory (if desired)

## Security Best Practices

### For Users

1. **Keep sing-box updated**: Always use the latest stable version
2. **Monitor security advisories**: Check the Security tab regularly
3. **Use secure configurations**: Follow security recommendations in the documentation
4. **Report suspicious activity**: If you notice unusual behavior, report it immediately

### For Contributors

1. **Security review**: All code changes undergo security review
2. **Dependency updates**: We regularly update dependencies to patch known vulnerabilities
3. **Code scanning**: We use GitHub CodeQL and other tools for automated security scanning
4. **Secure development**: We follow secure coding practices and guidelines

## Security Features

sing-box includes several security features:

- **TLS/SSL support**: Secure transport layer protocols
- **Certificate validation**: Proper certificate chain validation
- **Encryption**: Strong encryption algorithms for data protection
- **Access control**: Configurable access controls and authentication
- **Audit logging**: Comprehensive logging for security monitoring

## Vulnerability Disclosure Policy

### Timeline

- **Critical vulnerabilities**: 7 days from confirmation to patch
- **High severity**: 14 days from confirmation to patch
- **Medium severity**: 30 days from confirmation to patch
- **Low severity**: 90 days from confirmation to patch

### Disclosure Process

1. **Private disclosure**: Vulnerabilities are kept private during investigation
2. **Coordinated disclosure**: We coordinate with affected parties when necessary
3. **Public disclosure**: Security advisories are published after patches are available
4. **CVE assignment**: We request CVE IDs for significant vulnerabilities
